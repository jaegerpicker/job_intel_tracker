# Security model

Single human owner, approved agents, private data. No registration, first-login ownership, cloud model calls, scraping, automatic external communications, analytics or remote script dependencies.

Apple authorization-code flow uses one-time five-minute server state, browser-bound Secure/HttpOnly/SameSite=None flow cookie for cross-site `form_post`, nonce, server-side ES256 client secret and code exchange, Apple JWKS/RS256 signature verification, issuer/audience/expiry/required claims, and preconfigured stable owner `sub` allowlist. No email-based authorization. Session tokens are random and stored hashed, expire after eight hours, and use Secure/HttpOnly/SameSite=Lax cookies outside isolated demo. Logout invalidates server session. Mutation requests require a per-session CSRF header and reject foreign Origin. Bearer requests are scope-authorized separately and never authenticate through cookies alone.

Per-agent random credentials are shown once in the owner API response and stored only as SHA-256 hashes, with expiry, revocation, named attribution and job restrictions. Owner cookie plus CSRF is required for issuance/revocation; no credentials are generated at app startup or by demo. Credentials are not displayed in the UI. A read-only credential is the recommended starting scope. File scopes are separate. Every resource read/write/download/export checks authentication/authorization. Existing owner job states may be changed only with explicitly granted job write scope; owner decision fields stay protected. Agents can edit their own contributions, not another rater's. Attribution comes from authentication, never imported text.

SQLite transactions protect record versions, active cap, primary-role constraints and idempotency. Record revisions retain editor/body/timestamp history. Audit records actor/action/resource/time; it is an application audit, not an externally signed or tamper-proof log. Backups contain private information. Deletes purge records/revisions/materials but leave minimal audit identifiers. Idempotency results can retain prior payloads until maintenance; backups and storage need owner-managed retention.

The UI builds user content with `textContent`, never raw HTML. Links permit HTTP/HTTPS only. CSP forbids third-party scripts, framing, inline execution and arbitrary form targets. Downloads are authenticated `application/octet-stream` attachments with nosniff; original filenames cannot control storage paths. Storage uses random server IDs, extension allowlist, signature checks, 5 MiB file limit and restrictive directory permissions. Files are not executed, expanded or previewed. These checks are **not antivirus**; do not open unknown attachments without the appropriate local protections.

Before Internet exposure: configure TLS/reverse proxy body limit (6 MiB), request timeouts and rate limiting, trust proxy headers only from that proxy, protect/patch the host, restrict volume permissions, monitor disk space and protect private backups. The app alone does not offer distributed rate limiting, disk quotas, antivirus, encryption at rest or multiple-instance database support. Proxy access/error logs must exclude query strings, Authorization, cookies, callback bodies and tokens. Use `--no-access-log` for application runs; never enable debug tracing on real credentials. Dependencies are pinned in `requirements-lock.txt`; periodically review and update them.

Report security issues privately to the repository owner; do not attach real tokens, resumes or job records to public issues. This implementation has automated security integration tests, not an independent penetration-test certification. Live Apple configuration and browser cross-site callback behavior still require the setup protocol.

## Native mobile sessions (disabled by default)

The optional native handoff requires `MOBILE_AUTH_ENABLED=1`, an existing approved Apple owner subject, canonical HTTPS `PUBLIC_BASE_URL`, and `MOBILE_REDIRECT_URIS` as a JSON array of canonical HTTPS callback URLs on the exact canonical API origin, ending in `/auth/mobile/callback` (no query, fragment, credentials, custom schemes, or arbitrary redirect parameters). Configure only app-owned verified Universal/App Links after native entitlements and domain association are reviewed. This code does not configure those links, register providers, or alter deployed settings. Google remains unsupported and fails closed.

`POST /auth/mobile/start` accepts Apple, a random client state, an S256 challenge and an allowed redirect. Its five-minute browser ticket carries no authority by itself. The system browser uses the existing Apple signature/issuer/audience/nonce/owner verifier and cookie session. A signed-in owner must explicitly approve the handoff on a same-origin synchronizer-CSRF form; opening an attacker-chosen login link cannot silently issue a native credential. The server then redirects a random, hashed, single-use code, bound to the exact redirect and PKCE challenge. Codes expire after 60 seconds; serialized SQLite redemption consumes the code atomically. If an exchange response is lost, restart login; code redemption is deliberately not replayable.

`POST /auth/mobile/exchange` creates a `mobile_`-prefixed, hashed 15-minute owner bearer session, with no refresh credential. It permits record reads, ordinary job/status, note and interview-prep writes, and attachment metadata. It denies search-policy changes and cap overrides, research/rating writes, and attachment binaries, uploads, record deletion, exports, audit and agent management. Browser administrative operations explicitly reject every bearer even if its actor is owner. Bearer writes retain the existing record version and actor/idempotency key protections; browser writes retain Origin/CSRF checks. `POST /auth/mobile/logout` revokes the native session idempotently; browser sessions remain separate. Native sessions expire and fail closed, and disabling native auth invalidates their authority. Native session tokens and handoff codes are persisted only as hashes. The separate Apple flow binding stores the raw five-minute browser continuation ticket so the fixed internal authorization page can resume after provider verification; this ticket cannot authorize a session without the owner browser cookie and explicit CSRF approval. Generic native error responses avoid echoing submitted secrets.

Authorization tickets and one-time callback codes necessarily appear in handoff URLs. They must never be logged, copied to analytics/crash reports, screenshots or clipboard; redact query strings for `/auth/mobile/*` and app callback URLs in any future proxy/access logging before enabling this feature. HTTPS, PKCE, exact callbacks, explicit browser approval, `no-store` and `no-referrer` constrain interception; they do not replace app/domain ownership verification. Production activation still needs approved native entitlements, domain association, safe native Keychain/Keystore storage, and end-to-end acceptance against the real owner provider. No production keys, tokens, grants, migrations, deployment or enrollment are performed by this local implementation.
